# cyacc.cn 媒体上传 400 修复 — 2026-10-23

## 原因与处理

线上 `/api/admin/media` 上传返回 400。检查发现 `cyacc-blog_uploads` 卷在容器内的 `/app/uploads` 属于 `0:0`，权限为 `0755`；博客进程使用 `10001:10001`，不能创建文件。应用将存储 IOException 映射为“图片读取或存储失败”及 400。浏览器 LanguageDetector 提示与上传无关。

镜像本身的上传目录属主正确；现有数据卷的权限没有继承镜像目录的属主。此次确认了运行卷权限问题，没有将其归因于图片格式、数据库或证书。

先确认挂载为生产媒体卷，再仅将其根目录属主修复为 `10001:10001`，保留 `0755`。没有递归改权限，没有更改已有文件、正式内容和站点设置。

## 防止复发

- Compose 新增一次性 `media-init`，在服务启动前设置媒体卷根目录属主及用户写入权限。使用现有后端镜像，禁用网络、只读根文件系统，仅保留 CHOWN/FOWNER 能力；博客进程仍以普通用户运行。
- 后端健康检查同时验证媒体目录可写、可进入与公开 API 可用，避免上传不可用时仍显示健康。
- 运维容器的媒体挂载设置 `nocopy`，防止它向空卷复制自身目录元数据；挂载继续保持只读。
- `scripts/test-media-volume.sh` 使用临时独立卷验证 root 属主错误、重复初始化、普通用户写读删，以及已有文件内容、属主、权限保持不变。只清理带本次测试标签的卷。

本次只修改部署配置，无应用镜像重建或数据库迁移。部署修订标签为 `ecs-2026-10-23.3`；运行目录、应用镜像标签仍为 `ecs-2026-10-23`。
