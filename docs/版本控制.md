# 版本控制与 GitHub

当前分支 `main`，原始资料和每个通过验收的阶段分别提交。

| 标签 | 内容 |
| --- | --- |
| v0.0.0-plan | 原始资料与开发方案 |
| v0.1.0-core | 认证与版本化文章 |
| v0.2.0-services | 五类内容、媒体、站点、统计适配 |
| v0.3.0-public | 公开前台 |
| v0.4.0-admin | 后台与浏览器验收 |
| v1.0.0 | 部署、恢复、安全检查和首版交付 |

查看历史：`git log --oneline --decorate`。比较阶段：`git diff v0.3.0-public..v0.4.0-admin`。后续建议创建 `codex/<功能名>` 分支，测试通过再提交。

临时查看旧版本：

```bash
git status
git switch --detach v0.4.0-admin
# 查看结束
git switch main
```

撤销提交保留历史：`git revert <commit>`。不要强制覆盖未提交文件或把 `reset --hard` 当常规回滚。旧代码未必兼容新数据库；数据库通过备份恢复到新库，验证后切换。

尚未配置 remote，也没有推送。创建空 GitHub 仓库后执行：

```bash
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
git push origin --tags
```

推送前检查 `git status` 与 `git diff --cached`。本地凭据、媒体、备份、依赖和构建输出已忽略。GitHub Actions 自动验证 push/PR，不会自动部署；建议两个验证 job 均设为合并保护条件。浏览器 trace 可能含会话，所以 CI 不上传 trace、凭据或备份。
