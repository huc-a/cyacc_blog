## 鉴权检查

| 项目 | 实现及结论 |
| --- | --- |
| 管理权限 | 除明确公开及认证入口外，后端统一要求 ADMIN；不依赖前端隐藏按钮。单管理员，无访客注册接口。 |
| 密码 | 当前数据库仅 1 个启用账号，使用 BCrypt，cost 12；未导出密码或哈希。首次初始化和改密至少 12 字符。 |
| 会话 | 服务端会话、登录更换 session ID、最多 5 个并行会话、8 小时超时；退出失效，改密撤销其他会话均有测试。 |
| CSRF | 登录和状态修改使用会话 CSRF 令牌；匿名带正确 CSRF 仍不能写，登录缺令牌/错误令牌仍被拒绝。 |
| Cookie | 本地实际检查 HttpOnly、SameSite=Lax。生产 Compose 默认 Secure=true；真实 HTTPS 链路下的 Cookie 行为仍需目标环境验收。 |
| 公开信息 | 公开列表/详情只读冻结发布版本，下线/回收不可读；配置不含数据库或 Umami 凭据；管理员头像没有公开引用时不公开。 |
| 输入与媒体 | 参数绑定、分页上限、危险链接拒绝；Markdown 禁用原始 HTML；图片解码/重编码、大小/像素/GIF 帧限制及引用保护有测试。 |
| 登录限流 | 应用每来源每分钟 10 次，Nginx 另有限流。但当前生产代理链未完成真实客户端 IP 传递配置，见下方必做事项。 |

**真实客户端 IP 是尚待完成的部署项。** Java 限流使用 `request.getRemoteAddr()`；当前 Nginx 传递 X-Forwarded-For，但应用未配置可信转发头解析。加上宿主 HTTPS 代理后，各层看到的地址可能都是前一层代理，导致不同访客共享登录额度。部署时需要按实际网络仅信任明确的代理来源，逐层覆盖/解析客户端地址；验收两个不同来源分别限流，并确认伪造 X-Forwarded-For 不能绕过。不能直接信任任意公网请求中的转发头。

恢复包使用 `--no-owner --no-acl`，切换为生产替代环境前必须重新配置对象归属及迁移/运行角色权限。不能因为隔离恢复读得通，就以超级用户启动正式服务。
