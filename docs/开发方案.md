# 开发方案

## 需求理解

已读取 `博客开发.md`、`数据库设计.md`、`测试与安全准入流程.md`，分析前台及完整后台 HTML、内嵌统计原型、design-tokens.json 和三套 SVG 背景。

目标是单管理员个人博客，无访客注册。内容覆盖技术分享、学习笔记、作品、教程、网站收藏及优惠资源。原型中的合成访问数据、虚构作者、localStorage 内容存储和占位操作不能当作正式功能。

前台：首页三栏布局（作者/分类/标签、内容流、动态/日历）、五类栏目、分类标签筛选、搜索分页、内容阅读与教程章节、关于页、响应式导航、阅读设置。后台：工作台、内容筛选/编辑/预览/发布、分类标签、回收站、媒体、外观预览应用、站点与管理员设置、真实统计接入、审计和备份。

视觉沿用原型的雾山全景背景、暖纸底色、橄榄绿与棕色强调、18px 圆角、18px 磨砂、19px 衬线正文、1.95 行高。后台以稳定浅底表格与表单保证可读性，手机上侧栏收起。

## 架构与实施决定

1. 一个 Nuxt 工程承载 SSR 前台和客户端后台，统一同域 `/api` 代理；Spring Boot 按 auth/content/media/site/analytics/system 分包。
2. 采用本机 Java 17，Spring Boot 3.5 系列；Nuxt 4、Vue 3、TypeScript。Naive UI 用于后台交互，Markdown 编辑与阅读共用安全渲染，ECharts 用于真实统计。TOAST UI Editor 先验证适配性，不因编辑器阻断内容闭环。
3. PostgreSQL 正式库与测试库隔离；使用 Flyway 版本化迁移与 MyBatis 参数绑定。开发环境使用已安装 PostgreSQL 的独立项目实例，绝不接管已有数据库。CI 使用 PostgreSQL 服务容器运行同一套集成测试。
4. 内容主表与版本表分离，冻结版本不可编辑。已发布内容第一次改稿复制出工作版本；保存不切换公开指针；发布事务检查详情、冻结并切换指针。所有修改要求乐观锁；冲突返回 409。
5. slug 创建后固定，回收站继续占用；恢复内容进入下线/草稿状态，需明确发布才重新公开。永久删除不作为首版必需操作，保留回收站和历史以便恢复。
6. 五种专属详情跟随版本；教程整体发布，章节稳定标识跨版本保留；分类与标签关联、封面和媒体引用跟随版本。
7. 服务器会话与 CSRF 防护；管理员密码只存 BCrypt 哈希；生产 Cookie Secure/HttpOnly/SameSite。初始化凭据通过环境提供，不提交密码。
8. Markdown 禁用原始 HTML，危险协议拒绝；上传接收经过解码验证和重编码的 PNG/JPEG/GIF（GIF 自 v1.1.0 起逐帧处理；WebP 需解码器支持后开放），限制体积、像素和帧数，随机存储键；引用媒体不可删除。
9. 外观和站点配置采用白名单结构、乐观锁和显式应用。公开接口只返回公开配置；Umami 凭据仅保留服务端。
10. 统计接入 Umami；未配置、超时和无数据必须分别展示，不生成假数据。首版外链仅展示，不自动抓取；核验以人工记录为主。
11. 原型里的音乐、密码文章、定时发布不是当前需求的业务闭环，不凭占位 UI 推导新增范围。后续再独立规划。

## 阶段及硬性验收门槛

| 阶段 | 交付 | 通过后才能继续的验证 |
| --- | --- | --- |
| 0 规划与版本基线 | 本方案、需求映射、Git 初始化、忽略规则 | 原始文件完整、Git 状态与基线提交检查 |
| 1 后端核心 | 数据迁移、管理员会话、CSRF、文章草稿与发布、搜索、回收站、审计 | 真实 PostgreSQL 空库迁移；权限/CSRF/退出；草稿隔离；发布回滚；错误指针；并发冲突；下线/回收/恢复 |
| 2 内容与站点能力 | 其他四类详情、教程章节、分类标签、媒体、配置、账号、统计适配 | 各类型隔离及发布完整性；章节顺序；危险链接；上传伪造/超限；引用删除拦截；设置冲突；统计不可用状态 |
| 3 前台 | 原型风格首页、栏目、详情、搜索、阅读体验、SEO | 类型检查/构建；真实接口的公开页面、过滤、搜索、404；手机布局；Markdown 安全 |
| 4 管理后台 | 登录、工作台、五类编辑器、媒体、外观、设置、统计、审计 | 浏览器真实流程 A/B/C；过期会话与错误提示；保存冲突；草稿/发布/下线；响应式操作 |
| 5 交付与恢复 | 部署容器、Nginx、CI、备份恢复脚本、运行文档 | 全量测试；生产构建；依赖检查；隔离数据库与媒体恢复演练；Git 交付标签 |

每阶段记录实际命令、测试结果与限制，测试失败先修复，禁止把未跑测试写成通过。开发提交使用 `docs/feat/fix/test/chore` 分类；阶段通过后建立可回滚标签。代码回滚使用 `git switch --detach <tag>` 查看或 `git revert` 撤销，数据库通过备份与前向迁移恢复，不盲目降级 SQL。

## 6 首页个性化（v1.1.0）

按用户浏览器批注实施：导航搜索向左展开，取消清晰阅读按钮和欢迎条，顶部透明/滚动加深，栏目使用 SVG 图标；个人卡片用过半画面展示头像，移除统计并显示 GitHub/邮箱；页脚可填写 ICP 备案号。公安备案暂不显示。

先扩展站点配置和媒体引用，验证 GIF 逐帧重编码与 V2→V3 数据保留；再完成前后台界面并通过类型检查；最后用真实 Chrome 验证上传、预览、应用、搜索、滚动、手机布局和全部原有流程。更改经验收后合并到 main 并建立 v1.1.0 标签。升级前停写并保存数据库与媒体备份，具体结果见阶段验收记录。

## 7 卡片与紧凑导航（v1.2.0）

按第二轮 7 条浏览器批注调整：搜索改成栏内紧凑展开，个人介绍缩短且联系方式只留图标，整卡链接与封面文字叠层，分类/标签/时间放入不透明底栏，便签提高透明度，版权备案居中并移除页脚后台入口。栏目搜索使用同一展开组件，保留栏目内筛选与清除。

先验证列表标签的发布版本隔离，再以真实 Chrome 检查封面、正文区、信息栏及键盘的详情跳转，验证两处搜索、手机布局和旧有管理功能。阶段通过后创建 v1.2.0 标签。无新数据库迁移，可使用 v1.1.0 回滚本轮代码。

## 交付边界

本轮实现可运行并经验证的第一版，提供 Git 历史及 GitHub CI/推送指引。用户未提供 GitHub 仓库、生产域名、服务器和 Umami 实例，因此不创建远程仓库、不对公网部署；相关参数使用环境配置。真实生产流量统计需配置真实 Umami。示例内容仅在显式演示初始化中创建并清晰注明。
