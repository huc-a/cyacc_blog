# 备份与恢复

完整备份包含 PostgreSQL 自定义格式 dump、媒体 tar、SHA-256 清单、表记录数和图片引用。后台“导出内容 JSON”仅含当前工作稿，不替代完整备份。备份含密码哈希和草稿，应限制权限、加密异地保存，不能提交 Git。

## 本机备份

先在后端终端 Ctrl+C 停止写入，然后执行：

```powershell
$env:PGHOST='127.0.0.1'
$env:PGPORT='55432'
$env:PGUSER='postgres'
python scripts/backup.py --pg-bin D:/Tool/Postgres/bin backup --database caiya --media .local/uploads --out .local/backups/backup-20261021
```

输出目录必须不存在。工具默认检查本机 8080 无服务，并比较备份前后的媒体哈希和表记录数。容器/远程维护使用 `--quiesced` 时，操作者必须已停止所有写入服务，该参数不会自行停服。

另行保存 Git 标签、部署 `.env`、HTTPS 配置与证书。凭据存入密码管理器或加密备份，不会自动进入内容备份包。

## 生产备份

```bash
bash deploy/backup.sh
```

脚本构建运维镜像，停止 Nginx/Nuxt/Java，导出数据库和媒体，退出后尝试恢复原应用；PostgreSQL 保持运行。默认输出 `.local/backups/backup-<UTC时间>`，可在 `.env` 设置 `BACKUP_DIR`。完成后检查应用健康并异地保存。建议每日和升级前备份；本轮没有创建定时任务。

## 隔离恢复

目标必须命名为 `caiya_restore_<name>`，且数据库和媒体目录均不存在。工具不会 drop 原库或覆盖目录；校验 tar 路径，禁止符号/硬链接和路径穿越，并验证哈希、逐表数量和媒体引用。

```powershell
python scripts/backup.py --pg-bin D:/Tool/Postgres/bin verify --bundle .local/backups/backup-20261021
python scripts/backup.py --pg-bin D:/Tool/Postgres/bin restore --bundle .local/backups/backup-20261021 --target caiya_restore_check --media .local/restored-check
```

Linux 同样支持，安装 PostgreSQL 18 客户端，通过 PGHOST/PGPORT/PGUSER/PGPASSWORD 或 `.pgpass` 连接。密码不要放进命令参数或日志。恢复使用 `--no-owner --no-acl`；转为生产替代环境时，需要重新配置迁移/运行角色授权，再切换应用连接。

容器备份可复制到独立验证主机，使用同一工具恢复。需要在 Docker 内隔离验证时挂载一个独立目标媒体卷：

```bash
cd deploy
docker compose run --rm --no-deps -v caiya_recovery_check:/restore-target ops restore \
  --bundle /backups/backup-YYYYMMDDTHHMMSSZ --target caiya_restore_check --media /restore-target/files
```

恢复后用独立端口运行 Java，DB_URL/MEDIA_DIR 指向恢复目标，验证登录、公开版本、教程、封面和背景。通过后在维护窗口切换正式连接，保留旧位置。不要直接在原库执行降级 SQL。
